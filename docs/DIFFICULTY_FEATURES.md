# B1 revision: character-specific tradeoffs

**Design proposal, not implemented.** On 2026-10-26 the owner redirected B1 toward additional character-specific features that make play harder. Draft PR #100's numerical reductions are superseded and must not merge. This proposal starts from `ffc52bf`, with the original damage multipliers, health, pickups, durations, reward amounts and resource prices retained except for the explicit new conditions below. Installed `f8b2b0b` is preserved.

These are original gameplay interpretations of the existing meme themes, not claims about actual providers or majority opinion. The intended difficulty comes from target choice, timing, positioning and preparation. A native main attack always remains available. No new enemy, health tax, random shot failure, hidden penalty, company logo or real-person enemy is introduced. The DeepSeek 1.3x non-tear rule, GLM's lack of a forced active, fixed looks and the multiple-pocket DROP restriction stay unchanged.

## Proposed rules for all 22 forms

All times below are active, unpaused gameplay time. Conditions apply to the intrinsic character ability only, never to a standalone item with a similar name. A rejected activation retains its resource. HUD/captions must state the condition and the way to satisfy it. Initial numbers are reviewable design parameters, not accepted balance.

## Scope and implementation requirements

- Keep all approved baseline numerical benefits. Additional conditions need visible English cues; do not silently alter input. No new button, action chord or forced movement.
- The GPT/Grok/Kimi conditions consume the existing paid-attack identity observations; they must not alter child-laser classification, native attack timing or resource billing. Same-attack aggregation requires a bounded end-of-update decision so callback order cannot decide a penalty. Native E2 still gates any ancestry fix.
- Save primitive state per player with explicit version migration: pending age challenge, review state, reserved Compute, Adapter install progress, pinned-build clears and stored Pounce direction. No entity serialization. Target-dependent room state must store stable scalar identifiers or end safely without granting extra reward. Continue, type changes and co-op reassignment require regressions; real restart remains unaccepted.
- Cancellation/refund must be idempotent. A Rice cancellation can refund only its own spent Bowl once and cannot cancel an unrelated meal. Reserved Compute returns at most once, and cap/BR changes must never duplicate or destroy more than the existing clamp permits.
- Preserve the existing clear dedupe, pause, death, duplicate-callback and room/floor guards. Targets that become friendly, invulnerable, removed or leave the room must not leave a permanent restriction. GLM/Grok line-of-sight checks use native Room APIs, with engine cases for doors and obstacles.
- Implement on one main-based B1 revision branch, keep the PR unmerged until the revised table is accepted, and use targeted failing-first tests for every new condition plus unchanged-control cases. Reconcile EID, dossiers, README numbers/rules and acceptance records before presenting it as ready.

## Verification boundary

This document is the proposed rule set only. It does not establish that the new features are implemented, fun, balanced or compatible with every weapon. The initial numerical draft's 69 passing suites do not validate these mechanics. Each form needs its own before/after case and a later ordinary run. The original base-value inventory below is retained for comparison, not as evidence of vanilla parity.

## Baseline and comparison method

Health below is **whole hearts**: R red, S soul, B black. The mod XML uses half-heart units: `hp=4, armor=2` means 2R+1S. All 22 forms have zero black hearts. Pickups are coins/bombs/keys. Stat modifiers are relative to the native pre-item/cache value, not a fixture's artificial damage of 10. D damage, I firing interval (`MaxFireDelay + 1`), V movement speed, Rg range units, SS shot speed. Unlisted modifiers are unchanged native defaults; colors do not change combat stats. BR means Birthright. At a fresh start, normal Claude has zero account age; Qwen starts with Range selected but inactive, and tainted Qwen starts Balanced.

Sources: baseline `content/players.xml`, each named character module in `scripts/characters/`, `model_roster.lua`, and the bundled vanilla `resources-dlc3/players.xml`, inspected privately. No extracted vanilla files or artwork are included. The [players.xml API reference](https://wofsauge.github.io/IsaacDocs/rep/xml/players.html) confirms health units. Lua, rather than XML, supplies this mod's cache modifiers and three pocket actives.

Vanilla references are the closest useful comparison by starting health or play pattern, not claims of identical DPS or overall difficulty. Isaac's XML gives 3R and a bomb; Cain 2R and a key; Judas 1R and three coins; Eve 2R; Samson 3R; Lilith 1R+2B and `canShoot=false`. Their native items/unlocks and other strengths matter. This audit cannot prove any complete form clearly stronger than vanilla without ordinary runs. Equal total health with more soul hearts is also not equal survivability. The table identifies where a visible gameplay tradeoff can fit while preserving each existing numerical benefit.
